Project guide · Japanese Word Kitchen

How the app fits together

app.js is the coordinator, not the whole app. The page shell loads it, it connects user actions to the screen and project rules, and smaller files provide the screen content, artwork, data, storage, and checks.

One action through the code

Direct imports from app.js: components/home.js, components/reveal.js, components/study.js, both data/ files, both state/ files, and utils/speech.js, utils/storage.js, and utils/vocabulary.js.

Indirect connections: home.js imports the word/review screens and restaurant art; study and review screens import pronunciation/render helpers; reveal imports character art and dish rendering; session rules import the shuffle helper.

A three-stop route through one saved word

1

The action and state change

Open app.js and find handleAction, then the rate action. A 1–2 rating adds that card to missedWords.

2

Saving and restoring

In app.js, find persistProgress. Then open utils/storage.js and compare saveProgress with loadProgress.

3

The evidence

Open tests/storage.test.js and find “progress loads and saves custom words”. It checks that the same progress data comes back after saving and loading.

Project file inventory

This is every tracked project file, grouped by its job. Workflow-only local files are not part of the app.

Browser entry and coordination

  • index.html — document shell, app mount point, stylesheet, and JavaScript entry.
  • app.js — startup, saved app state, screen selection, button/form routing, and storage coordination.
  • styles.css — layout, colors, typography, illustrations, and responsive styling.

Screen and artwork components

  • components/home.js — restaurant home, sidebar navigation, and screen layout.
  • components/study.js — study tabletop and vocabulary card.
  • components/vocab.js — add/edit/remove word form and custom-word list.
  • components/review.js — missed-word review card.
  • components/reveal.js — dish reveal, served screen, and aunties' counter ending.
  • components/restaurant.js — restaurant and character illustration markup.
  • components/pronunciation.js — Japanese pronunciation button markup.

Content and behavior

  • data/dishes.js — dish names, ingredients, facts, and artwork data.
  • data/vocabulary.js — built-in English–Japanese word pairs.
  • state/session.js — study-session setup, ratings, dish outcomes, and fact rotation.
  • state/review.js — rules for keeping or clearing reviewed missed words.

Shared helpers

  • utils/render.js — safe text handling and dish artwork rendering.
  • utils/shuffle.js — random ordering for sessions.
  • utils/vocabulary.js — required-field and duplicate-pair checks.
  • utils/speech.js — browser Japanese speech synthesis.
  • utils/storage.js — browser-local progress loading and saving.

Automated checks

  • tests/render.test.js — screen output, illustration, and counter-message checks.
  • tests/session.test.js — session, rating, vocabulary, review, and fact-cycle rules.
  • tests/speech.test.js — speech support, voice loading, and errors.
  • tests/storage.test.js — saved progress, unavailable storage, and fact-cycle restoration.

Running and project support

To change this, start here

Button flow or when a screen changes: app.js, handleAction.

Screen layout or component copy: the matching file in components/.

Dish content or built-in words: data/dishes.js or data/vocabulary.js.

Study and review rules: state/session.js or state/review.js.

Saved fields or browser-storage behavior: utils/storage.js.

Page appearance: styles.css.

A practice to reuse

Trace a visible action through its state update and persistence, then check the expected behavior with a focused test. Here, app.js records a low-rated word, utils/storage.js saves it, and tests/storage.test.js checks a save/load round trip. The project's 25 automated tests pass.

Run it again

  1. From the project folder, run python3 -m http.server 8000.
  2. Open http://localhost:8000.
  3. Run checks with npm test.
